# SePlatform Deploy Tool

Автоматизированное обновление программного комплекса **SePlatform / Systeme Soft** на
клиентских Windows-машинах, работающее напрямую с машины клиента.

Инструмент не требует Git, Ansible или внешних систем. Единственный вход — ZIP-архив с
дистрибутивами и этот проект, скопированный на машину.

---

## Назначение

Инструмент выполняет доведение установленной SePlatform до версий из указанного архива:

1. анализирует архив и извлекает информацию о MSI-пакетах (белый список из `manifest.json`);
2. инвентаризирует установленные компоненты SePlatform по реестру (обе архитектуры);
3. сопоставляет установленные версии с версиями из архива;
4. проверяет зависимости;
5. показывает план изменений;
6. требует одно подтверждение;
7. по подтверждению: старые версии удаляются, новые устанавливаются через `msiexec`,
   результат проверяется повторной инвентаризацией;
8. пишет подробные логи в отдельную директорию сессии и `report.json`.

**Принцип:** никакого массового удаления/установки по имени `SePlatform*`. Работа
разрешена только с компонентами, явно перечисленными в `manifest.json`.

---

## Требования

- Windows 7 x64 / 10 / 11 (x86 не поддерживается);
- PowerShell 5.1 и выше (входит в состав Windows);
- запуск **от имени Администратора** (для фактического развёртывания);
- ZIP-архив с HMI (например, `X:\HMI 2.0.38.zip`);
- для Development Studio 2.0.x требуется .NET 8 Desktop Runtime 8.0.14+ (проверяется,
  но не устанавливается автоматически).

Инструмент не устанавливает и не изменяет стороннее ПО: 7-Zip, .NET, Python,
Visual C++ Redistributable, OpenLDAP, VMware Tools, Wireshark, Edge/WebView2, OPC
и прочее — даже если они установлены на машине.

├── Deploy.ps1            # точка входа

## Запуск

Откройте PowerShell **от имени Администратора** и выполните:

```powershell
.\Deploy.ps1 -Archive "X:\HMI 2.0.38.zip"
```

Пример полного пути к проекту:

```powershell
cd "C:\Users\dwbpr\Desktop\SEP_update_tool\SePlatform-Deploy"
.\Deploy.ps1 -Archive "X:\HMI 2.0.38.zip"
```

### Сухой прогон (без изменений)

```powershell
.\Deploy.ps1 -Archive "X:\HMI 2.0.38.zip" -WhatIf
```

В этом режиме выполняются только инвентаризация, анализ архива, проверка зависимостей
и вывод плана. Система не изменяется. Прав администратора не требуется.

### Параметры

| Параметр      | Описание |
|---------------|----------|
| `-Archive`    | Путь к ZIP-архиву. Если не задан, берётся `defaultArchive` из `config.json`. |
| `-Config`     | Путь к `config.json` (по умолчанию рядом со скриптом). |
| `-Manifest`   | Путь к `manifest.json` (по умолчанию рядом со скриптом). |
| `-LogPath`    | Корневая директория логов (по умолчанию `C:\ProgramData\SePlatform\Deployment`). |
| `-Locale`     | Предпочтение локали, например `ru_RU` или `en_US`. |
| `-WhatIf`     | Сухой прогон, nothing is changed. |
| `-AutoApprove`| Не запрашивать подтверждение; все отсутствующие компоненты устанавливать. |
| `-NonInteractive` | Без интерактивных запросов (полезно для автономного запуска). |
| `-UpdateOnly` | Обновить только установленные компоненты; отсутствующие не устанавливаются. |
| `-Uninstall`  | Режим удаления установленных компонентов. |
| `-KeepTemp`   | Не удалять временную директорию с MSI после запуска. |

> **Внимание:** `-NonInteractive` без `-AutoApprove` работает в режиме
> «установка и обновление» без запросов. Используйте осознанно.
> `-Uninstall` и `-UpdateOnly` имеют приоритет над выбором режима из меню.

## Интерактивное управление

При запуске **без** `-WhatIf`, `-AutoApprove` и `-NonInteractive` после анализа и
вывода плана показывается меню режимов:

```
Deployment mode:
  [1] Update existing components (do not install missing)
  [2] Install and update (including missing components)
  [3] Uninstall components
  [4] Exit
```

- **1 — Обновить существующие:** предлагает выбрать только компоненты, которые уже
  установлены и подлежат обновлению. Отсутствующие пропускаются.
- **2 — Установить и обновить:** предлагает выбрать из обновлений и отсутствующих
  компонентов.
- **3 — Удалить:** предлагает выбрать установленные компоненты для удаления
  (полностью или по номеру). Перед удалением выводится итоговое подтверждение.
- **4 — Выход:** завершение без изменений.

Во всех режимах выбор списком: `A` — все, `N` — ничего, `1,3,5` или `1 3 5` —
конкретные номера (проверяется корректность ввода).

В режимах `-Uninstall` / `-UpdateOnly` без `-AutoApprove` тоже предлагается
выбор по номерам.

## Что происходит при запуске

1. Проверка прав администратора (кроме `-WhatIf`).
2. Создание директории логов сессии:
   `C:\ProgramData\SePlatform\Deployment\YYYY-MM-DD_HH-mm-ss\`
3. Анализ ZIP: ищутся только MSI, соответствующие `installerPattern` из `manifest.json`.
   `.deb`, `.rpm`, `.msm`, `.zip`, документы и чужой софт игнорируются.
4. Извлечение выбранных MSI во временную директорию и чтение их свойств
   (ProductName, ProductVersion).
5. Инвентаризация установленных SePlatform по реестру
   (`HKLM\Software\...\Uninstall` и `HKLM\Software\WOW6432Node\...\Uninstall`).
6. Сравнение версий (нормализация форматов `2.4.36+b4.r151051`,
   `2.4.36.4`, `1.3.17.1` и т. п.).
7. Проверка зависимостей (для DevStudio — .NET 8 Desktop Runtime ≥ 8.0.14).
8. Вывод плана и запрос подтверждения.
9. Выполнение: остановка служб/процессов компонента → удаление старой версии
   (`msiexec /x {ProductCode}`) → установка новой (`msiexec /i ... /qn /norestart`)
   → повторная инвентаризация и проверка версии.
10. Итоговая сводка и `report.json`.

### Отсутствующие компоненты

В режиме «Установить и обновить» (или без указания режима) отсутствующие компоненты
не ставятся автоматически и предлагаются на выбор в общем списке:

```
[1] SePlatform.HMI.Charts  2.0.16.2  [not installed]
[2] ...
```

Выбор: `A` — установить всё; `N` — ничего не устанавливать;
`1, 3, 4` или `1 3 4` — конкретные номера (проверяется корректность ввода).

В режиме «Обновить существующие» (`-UpdateOnly`) отсутствующие компоненты
пропускаются без установки.

## Сравнение версий

Версии могут иметь разный формат:

- из реестра: `2.4.28.1`, `2.0.33.1`;
- из архива/имени файла: `2.4.36+b4.r151051`, `2.0.38+b101.r150713`.

Инструмент нормализует обе строки к числовому кортежу
`major.minor.patch.build.revision` и сравнивает поэлементно. Итоги:

| Ситуация | Результат |
|----------|-----------|
| Архив новее установленного | `UPDATE` (удалить старую версию, поставить новую) |
| Версии совпадают | `OK` / `SKIP` (идемпотентность) |
| Установленная новее архива | `SKIP` + warning |
| Downgrade | никогда не выполняется автоматически |

## Логи и отчёт

Каждая сессия создаёт директорию вида:

```
C:\ProgramData\SePlatform\Deployment\2026-09-21_14-30-00\
├── Deployment.log
├── DataServer-uninstall.log
├── DataServer-install.log
├── HMI-install.log
└── report.json
```

В логах фиксируются: время, компонент, старая/новая версия, действие, путь MSI,
exit code, результат и ошибки.

`report.json` содержит счётчики и по каждому компоненту: статус, версии, файл MSI,
exit-коды, результат проверки, ошибку.

---

## Exit codes

| Код | Значение |
|-----|----------|
| 0   | Успех: всё установлено/обновлено или уже актуально |
| 1   | Завершено с ошибками (хотя бы один компонент не удалось установить/проверить) |
| 2   | Отменено пользователем или прервано вводом |
| 3   | Зарезервировано для критических зависимостей (блокирующее условие) |
| 4   | Ошибка параметров/конфигурации: нет прав администратора, архив не найден, битый JSON |

---

## Идемпотентность

Повторный запуск при уже актуальном состоянии не выполняет удаление/установку:
каждый компонент проверяется, и если версия совпадает с архивом — выводится `[OK]`
и действие пропускается.

---

## Безопасность и ограничения

- Устанавливаются/удаляются **только** компоненты из `manifest.json` (whitelist).
- **Не используется** `Win32_Product` (ни для инвентаризации, ни для удаления).
- Downgrade никогда не выполняется автоматически.
- Сторонние зависимости (.NET, Python и др.) **не устанавливаются**.
- Конфигурационные файлы компонентов не удаляются: используется штатное поведение MSI.
- Процессы завершаются только для конкретных, перечисленных в manifest служб/процессов
  компонента; массовое завершение по `*Se*` невозможно.
- При ошибке удаления старой версии новая версия этого компонента не устанавливается.

Известные ограничения:

- Между ветками Data Server/DevStudio меняется формат идентификатора экземпляра
  (см. «ВАЖНО! ОБЯЗАТЕЛЬНО К ПРОЧТЕНИЮ.md» в архиве). Инструмент не управляет этим;
  оператор должен выполнить шаги миграции вручную.
- Переход Historian 1.x → 2.x меняет формат БД (3x → 4x) и требует миграцию данных по
  документации производителя. Инструмент не мигрирует данные.

## Инструкция оператору (объект)

1. Скопируйте папку `SePlatform-Deploy` на машину клиента
   (например, в `C:\SePlatform-Deploy`).
2. Убедитесь, что архив дистрибутива доступен (например, `X:\HMI 2.0.38.zip`).
3. Откройте PowerShell **от имени Администратора**.
4. Выполните сухой прогон и проверьте план:
   ```powershell
   cd C:\SePlatform-Deploy
   .\Deploy.ps1 -Archive "X:\HMI 2.0.38.zip" -WhatIf
   ```
5. Если план корректен, выполните развёртывание:
   ```powershell
   .\Deploy.ps1 -Archive "X:\HMI 2.0.38.zip"
   ```
6. В появившемся меню выберите режим (1/2/3/4) и, при необходимости, конкретные
   компоненты (`A`/`N`/номера), затем подтвердите `Y`.
7. По завершении проверьте сводку и пути к логам. При ошибках передайте инженеру
   содержимое директории сессии.
8. Для повторного запуска (идемпотентность) просто выполните команду из п.5 снова.

Для типовых сценариев без меню:

- Обновить только установленное (без установки отсутствующего):
  ```powershell
  .\Deploy.ps1 -Archive "X:\HMI 2.0.38.zip" -UpdateOnly -AutoApprove
  ```
- Удалить всё установленное:
  ```powershell
  .\Deploy.ps1 -Archive "X:\HMI 2.0.38.zip" -Uninstall -AutoApprove
  ```
- Удалить выборочно (список с номерами):
  ```powershell
  .\Deploy.ps1 -Archive "X:\HMI 2.0.38.zip" -Uninstall
  ```

---

## Проверка перед использованием

- PowerShell-синтаксис файлов проверен парсером;
- JSON (`manifest.json`, `config.json`) валиден;
- `manifest.json` построен по фактическому содержимому `HMI 2.0.38.zip`
  (лист совместимости, имена продуктов в реестре, свойства MSI);
- версии/ProductName/ProductCode взяты из реальных MSI архива и реального
  установленного комплекса.

**Требует реального тестирования на клиентской машине:** фактическое обновление
Data Server (остановка служб, uninstall/install), обновление HMI Desktop/WebViewer,
поведение при отсутствующем .NET 8, взаимодействие с активными сессиями HMI.
